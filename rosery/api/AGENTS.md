# Go API work

For any Go implementation, review, debug or setup task, load the `golang-how-to` skill and the relevant Go skills it selects. Use a small `cmd/` entry point and internal packages with explicit constructor wiring.

Keep Rosery free and accountless. Never embed Quran Foundation credentials or the origin secret in the mobile app. Protected routes must verify App Attest even for cache hits; do not introduce an unsigned production or simulator fallback. Preserve atomic challenge consumption and durable monotonic counters.

Run `make check`, `make lint` and a dependency vulnerability check for security changes. App Attest changes must retain the independent real-device proof test and the shared Swift/Go canonical request fixture. Actual signed-device interoperability is a separate integration check.

The bbolt state and process-local limits support one API process; use shared transactional state and distributed limits before introducing replicas. Persistent offline Quran content must use Quran Foundation's supported Content Sync flow and terms.
